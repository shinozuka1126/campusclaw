## Why

CampusClaw 的教研材料分散在群文件与网盘中，教师难以复用，班级之间也缺少数据边界。本变更先建立身份、角色与班级隔离，让教师登录后上传并管理本班材料，学生仅可查看本班内容，为后续检索与智能问答打基础。

## What Changes

- 教师、学生账号密码登录；未登录访问受保护页面时引导至登录页。
- 教师可上传和管理本班材料；学生只读，调用上传接口返回 403。
- 所有材料查询在服务端按会话班级过滤；跨班按 ID 访问返回 404。
- 教师上传 `.txt`/`.md` 后解析并写入知识库，本班列表从数据库查询展示。
- 预置 A/B 班、教师 A、学生 A1/B1、两班可区分材料和六类核心数据表。
- 密码哈希存储，`SECRET_KEY` 仅由环境变量注入；Docker Compose 与 `GET /health` 可复现启动。

## Capabilities

### New Capabilities

- `auth-upload`：登录与会话、角色授权、班级隔离、材料上传入库、预置数据、密码哈希、Compose 与 `/health`。

### Modified Capabilities

无。

## Impact

新建 Flask + SQLite 应用、模板、数据初始化脚本、Docker Compose 与验收测试。

## Non-goals

- 不做 RAG、全文检索、智能问答或对话助手。
- 不做作业提交、批改、成绩、审计与错题本。
- 不做注册、找回密码、OAuth/OIDC、SSO、多校多租户。
- 不做 K8s、多副本高可用或完整 CI/CD。
- 不以隐藏前端按钮替代服务端授权与班级隔离。
